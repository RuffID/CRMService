# AGENTS

Директория `Pages/Equipments` отвечает за UI списка оборудования и страницу карточки оборудования.

Что здесь находится:
- `Index` — AJAX-only список оборудования с фильтрами, поиском по id и постраничной навигацией;
- `Details` — страница маршрута `/equipments/{id}` для перехода из списка в карточку оборудования.

Пользовательский сценарий:
- пользователь ищет оборудование по id;
- фильтрует список по клиенту, объекту обслуживания, типу, производителю и модели;
- открывает карточку оборудования;
- открывает текущую карточку оборудования в Okdesk по ссылке из домена Okdesk и id оборудования;
- обновляет отдельную карточку оборудования из облачной API Okdesk по id и после завершения повторно загружает данные карточки из локальной БД;
- запускает ручное обновление всего списка оборудования из облачной БД Okdesk; на время обновления кнопка `Обновить` блокируется через состояние в оперативной памяти сервера;
- запускает доступы к оборудованию или серверу через кнопки в списке и карточке, если данные доступа валидны.

Связанная логика:
- серверная выборка списка и карточки находится в `CRMService.Application/Service/OkdeskEntity/EquipmentService.cs`;
- клиентский код списка находится в `CRMService.Web/wwwroot/js/equipments/equipments.js`;
- клиентский код карточки находится в `CRMService.Web/wwwroot/js/equipments/details.js`;
- серверное состояние и запуск ручного обновления списка оборудования находятся в `CRMService.Web/Service/BackgroundServices/EquipmentCloudDbUpdateService.cs`;
- параметры оборудования находятся в `CRMService.Domain/Models/OkdeskEntity/EquipmentParameter.cs`.

Правила изменений:
- список и фильтры должны повторять общий паттерн страниц Razor Pages + отдельный JavaScript в `wwwroot/js/equipments`;
- данные для UI загружать только через PageModel handlers, без серверного рендера коллекций;
- при расширении карточки оборудования держать маршрут `/equipments/{id}` стабильным;
- список оборудования должен укладываться в ширину страницы без ухода вправо за видимую область; для длинного текста сохранять многоточие и возможность ручного ресайза колонок, кроме `Id`: его ширина всегда определяется по максимальной ячейке, а расширение остальных колонок вправо не должно сжимать столбцы слева.
- ручное обновление из облачной БД должно запускаться только в одном экземпляре на процесс приложения; ошибки синхронизации логируются на сервере и не показываются пользователю на странице.
- кнопка ручного обновления из облачной БД доступна только пользователю с ролью `admin`; backend-handlers обновления также должны проверять эту роль.

Скелет для столбца `Доступы`:
- на странице оборудования в таблице должен появиться отдельный столбец `Доступы` с иконками действий;
- иконки запускают подключения к ресурсам через `clearbat`;
- примеры формата ссылок для запуска через браузер и правила `encode` описаны в корневом `AGENTS.md` в разделе `CLEAR.bat`;
- доступы вида `123 123 123 / password` и `123123123/password` перед разбором нормализуются удалением всех пробелов;
- после нормализации обязательно искать разделитель `/`; если разделителя нет или одна из частей пустая, доступ считается невалидным и запуск по нему невозможен;
- пока эти значения считаются опорным списком для разметки и дальнейшей логики маппинга, без фиксации финального UI-контракта.

Где искать данные для `Доступов`:
- код модели параметра находится в `CRMService.Domain/Models/OkdeskEntity/KindsParameter.cs`;
- фактическое значение параметра оборудования хранится в `CRMService.Domain/Models/OkdeskEntity/EquipmentParameter.cs`;
- само оборудование находится в `CRMService.Domain/Models/OkdeskEntity/Equipment.cs`;
- основная серверная обработка оборудования находится в `CRMService.Application/Service/OkdeskEntity/EquipmentService.cs`.

Доступы терминала:
- `AA` — `АмиАдмин логин/пароль`;
- `AC` — `Ассистент логин/пароль`;
- `AnyDesk` — `ЭниДеск логин/пароль`;
- `rust` — `RustDesk логин/пароль`.

Текущий минимальный сценарий в списке оборудования:
- в колонке `Доступы` на странице `Index` сейчас выводятся кнопки `AD`, `AA`, `AC`, `RD`, `RMS`, `Chain`;
- терминальные кнопки используют параметры `AnyDesk`, `AA`, `AC`, `rust` и типы `clearbat`: `anydesk`, `ammyy`, `assistant`, `rustdesk`;
- серверная кнопка `RMS` использует адрес из `srv_addr`;
- серверная кнопка `Chain` использует адрес из `0017`;
- для `RMS` и `Chain` логин и пароль берутся из параметра `0008` (`Iiko логин/пароль`);
- если в адресе сервера или chain не указан порт, по умолчанию нужно дописывать `:443`;
- если значение адреса приходит в формате `ip:port / пароль`, нужно выделять адрес `ip:port`, а пароль брать из этой строки и использовать его вместо пароля из `0008`;
- кнопки должны появляться только при валидной записи доступа и запускать подключение через `clearbat`.
- для `AnyDesk` пароль считается обязательным, потому что этот тип входит в список подключений, где `password` обязателен по правилам корневого `AGENTS.md`.
- для `AA`, `AC`, `RD`, `RMS`, `Chain` допускается попытка запуска без пароля, если после нормализации в значении есть только логин или пароль не заполнен.

Доступы к серверу iiko:
- `0008` — `Iiko логин/пароль`;
- `0017` — `Адрес сервера IikoChain`;
- `srv_addr` — `Адрес сервера`;
- для подключения использовать адрес сервера или chain-адрес вместе с логином и паролем iiko.

Web-ссылка:
- `1212` — `Ссылка на iiko WEB`;
- это обычная ссылка, которую нужно открывать в браузере без запуска `clearbat`.
