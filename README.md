## Назначение системы

CRMService — внутренняя CRM-система для просмотра и анализа данных по заявкам, оборудованию, сотрудникам и клиентам. Система собирает данные из внешней учетной системы (Okdesk (окдеск)), хранит локальную копию и дает сотрудникам единый веб-интерфейс для отчетов, поиска заявок, просмотра оборудования и администрирования пользователей.

Система рассчитана на пользователей с авторизацией. Обычный пользователь видит основные рабочие разделы, а администратор получает доступ к управлению планами, пользователями, настройкам сайта, заявкам и оборудованию.

## Общий принцип работы

Пользователь входит в систему под своим логином и паролем. После входа открывается интерфейс с боковым меню. Данные на рабочих страницах загружаются без перезагрузки всей страницы: пользователь применяет фильтры, открывает карточки, меняет настройки и сразу видит результат.

Данные по заявкам, оборудованию, клиентам, сотрудникам, справочникам и списанному времени регулярно обновляются из внешней системы. Часть обновлений выполняется автоматически, часть может запускаться вручную администратором, а отдельные изменения поступают через события внешней системы.

При объединении списанного времени обычный API и вебхуки обновляют актуальные данные, а SQL API дополняет отсутствующие служебные поля. Задержанный снимок SQL API не должен перезаписывать более свежие значения или очищать уже полученную дату создания списания.

Для заявок ответственная группа актуализируется вебхуками. REST-обновление списка заявок сохраняет уже известную локальную группу, а SQL-снимок обновляет заявку только тогда, когда его отметка обновления не старше локальной. Это не позволяет трехчасовому SQL-снимку перезаписать более свежее состояние, полученное через вебхук.

## Страницы системы

### Вход

Страница входа позволяет пользователю авторизоваться по логину и паролю. При успешном входе создается пользовательская сессия, после чего открывается защищенная часть системы. При ошибке входа пользователь видит сообщение и может повторить попытку.

### Главная

Главная страница служит стартовой точкой после входа. Сейчас она выполняет роль пустого дашборда и может быть расширена под краткие показатели, быстрые ссылки или статус системы.

### Отчёт

Страница отчетов объединяет несколько представлений:
- производительность сотрудников;
- динамика списанного времени;
- динамика созданных и решенных заявок.

В отчете производительности можно выбирать сотрудников, группы, приоритеты, статусы, типы заявок и период. По умолчанию в таблице показываются только активные сотрудники; фильтр можно отключить, и выбранное значение сохраняется в локальном хранилище браузера вместе с остальными фильтрами. Галочка «Показывать заявки без ответственного» позволяет выбрать несколько ответственных групп и добавляет внизу общую строку «Без ответственного» с суммарным количеством их открытых заявок без назначенного сотрудника. Для этой строки решенные заявки, план и списанное время не рассчитываются, а сама строка не увеличивает счетчик сотрудников. Доступны дополнительные режимы: скрытие строк без показателей, просмотр только текущего дня, переключение между планами и изменение масштаба шрифта. Столбец можно скрыть через контекстное меню его заголовка и вернуть через настройки по кнопке с шестерёнкой; выбранная видимость сохраняется в локальном хранилище браузера. Итоговая таблица показывает сотрудника или группу, количество решенных заявок, план, текущие заявки и списанное время.

График списанного времени показывает, как менялся объем списаний за выбранный период. Пользователь может смотреть данные по сотрудникам или по группам, выбирать ось времени, шаг детализации, период и состав участников.

График динамики заявок показывает количество созданных и решенных заявок за выбранный период с детализацией по часам или дням.

### Настройки планов

Страница позволяет администратору управлять планами, которые используются в отчетах. Здесь можно:
- задать общий интервал автоматического переключения планов;
- создавать, изменять и удалять планы;
- выбирать период плана;
- задавать цвет плана;
- настраивать цветовые правила выполнения в процентах;
- назначать плановые значения сотрудникам;
- фильтровать сотрудников по ФИО и группам.

Эти настройки влияют на отображение производительности сотрудников в отчетах.

### Настройки сайта

Страница настроек сайта сейчас отвечает за фон отчета. Администратор может загрузить изображение, посмотреть текущий фон, открыть предпросмотр и удалить файл. Система хранит только один актуальный фон: новая загрузка заменяет предыдущий файл.

### Пользователи

Страница пользователей предназначена для администрирования учетных записей. Администратор может:
- просматривать список пользователей;
- показывать или скрывать удаленных пользователей;
- создавать нового пользователя;
- редактировать имя, логин, пароль, роли и необязательную привязку к сотруднику Okdesk;
- включать или отключать пользователя.

Пользователь должен иметь хотя бы одну роль. Один пользователь может быть связан только с одним сотрудником Okdesk, а один сотрудник Okdesk — только с одним пользователем. Отключенные пользователи не должны рассматриваться как активные участники системы.

### Заявки

Страница заявок показывает список обращений из внешней системы. Пользователь может искать заявки по номеру или теме, задавать количество строк на странице и фильтровать список по:
- типу;
- статусу;
- клиенту;
- приоритету;
- ответственному;
- автору;
- ответственной группе;
- диапазону номеров;
- дате регистрации;
- дате решения.

Таблица показывает номер, тему, клиента, ответственного, даты регистрации и решения, а также статус. Колонки можно читать в широком табличном виде, список поддерживает постраничную навигацию. Из строки можно перейти в карточку заявки и вернуться назад к той же странице списка.

Карточка заявки показывает подробную информацию по выбранной заявке.

### Оборудование

Страница оборудования показывает список оборудования клиентов. Пользователь может искать оборудование по id, выбирать количество строк на странице и фильтровать список по:
- клиенту;
- объекту обслуживания;
- типу;
- производителю;
- модели.

Таблица показывает id, тип/производителя/модель, инвентарный номер, серийный номер, клиента, объект и доступы. Из строки можно перейти в карточку оборудования.

Администратор может вручную запустить обновление всего списка оборудования из облачной БД Okdesk. Пока обновление выполняется, кнопка запуска блокируется на сервере для всех пользователей; если другой пользователь попытается запустить обновление параллельно, он увидит сообщение с локальным временем запуска и именем пользователя, который уже начал обновление.

Для оборудования поддерживаются быстрые действия доступа. Если в параметрах оборудования есть корректные данные, система показывает кнопки для запуска подключений к терминалам, серверу или web-ссылке. Некорректные или неполные доступы не должны запускаться.

Карточка оборудования показывает подробные сведения по выбранному оборудованию и его параметрам.

### Страница отказа в доступе

Страница отображается, когда пользователь пытается открыть раздел без нужных прав или недоступный маршрут.

### Страница ошибки

Страница ошибки используется для отображения непредвиденных сбоев приложения.

## Автоматические процессы

Система поддерживает автоматическое обновление данных:
- периодическое обновление назначенных заявок и заявок, недавно оставшихся без ответственного;
- ежедневное обновление заявок и списанного времени;
- ежедневную сверку текущих локальных заявок с Okdesk, чтобы удаленные или объединенные заявки переставали учитываться в отчетах;
- обновление справочников, клиентов, сотрудников, оборудования и связанных сущностей;
- обработку входящих событий внешней системы по заявкам, клиентам, объектам обслуживания и оборудованию.

Администратор может вручную запустить полную сверку текущих заявок, если требуется проверить и очистить уже накопившиеся локальные записи, которых больше нет в Okdesk. HTTP-запрос ожидает завершения сверки и отменяет ее при разрыве соединения.

Цель автоматических процессов — поддерживать локальные данные актуальными для отчетов, списков и карточек.

## Роли и доступ

Доступ к системе требует авторизации. Администратор видит дополнительные разделы: планы, заявки, оборудование, пользователи и настройки сайта. Меню и доступность действий зависят от роли пользователя.

## Требования к сопровождению

При изменении пользовательского функционала нужно обновлять это техническое задание, если меняется назначение страницы, доступные действия, фильтры, автоматические процессы или общий принцип работы системы.

Для разработчиков рядом с важными директориями должны поддерживаться локальные `AGENTS.md` с кратким описанием ответственности директории и правилами внесения изменений.

## Резервные копии SQL Server

`SqlServerBackupService` выполняет `BACKUP DATABASE` внутри SQL Server. Для Windows и Linux задаются отдельные абсолютные пути, доступные SQL Server. Сервис выбирает путь по ОС процесса ASP.NET Core; это предполагает, что приложение и SQL Server работают на одной ОС.

```json
{
  "DatabaseBackup": {
    "ProjectName": "CRMService",
    "WindowsSqlServerPath": "C:\\SQLBackups",
    "LinuxSqlServerPath": "/var/opt/mssql/data"
  }
}
```

Имена файлов имеют формат `backup_CRMService_yyyyMMdd_HHmmss_fffffff_guid.bak`. `ProjectName` обязателен и может содержать буквы, цифры, дефисы и нижние подчёркивания. Оба каталога должны существовать и быть доступны службе или контейнеру SQL Server.

В Docker отдельный named volume для резервных копий можно настроить во внешней конфигурации развёртывания и указать его путь в `LinuxSqlServerPath`. `.bak` записывает непосредственно SQL Server. Volume переживает пересоздание контейнера базы данных; удаление volume также безвозвратно удаляет сохранённые резервные копии.

Для выгрузки `.bak` следует временно подключить backup volume к отдельному служебному контейнеру только на время копирования. Имена volume и способ передачи пароля SQL Server определяются внешней конфигурацией развёртывания; секреты не должны храниться в репозитории.
