# Подэтапы выполнения

## Этап 1. Анализ и контракты - выполнено

- Проверить, какие репозитории и сервисы уже можно переиспользовать для списка заявок.
- Зафиксировать набор новых DTO и request-моделей.
- Определить формат ответа для быстрого и точного подсчёта количества.

## Этап 2. Серверная часть списка - выполнено

- Добавить метод получения заявок с фильтрацией и пагинацией.
- Добавить метод быстрого подсчёта общего количества до порога `1000+`.
- Добавить метод точного подсчёта общего количества по отдельному запросу.
- Добавить валидацию входных фильтров.

## Этап 3. Серверная часть справочников - выполнено

- Поднять хендлеры для загрузки статусов и типов.
- Поднять хендлеры для загрузки сотрудников, авторов, клиентов и групп.
- Проверить, что все справочники возвращаются в формате, удобном для мультиселектов.

## Этап 4. Новая Razor Page - выполнено

- Создать страницу списка заявок.
- Собрать верхний collapsible-блок фильтров.
- Собрать секцию таблицы и секцию пагинации.
- Подключить скрипты страницы и общие JS-хелперы.

## Этап 5. JavaScript страницы - выполнено

- Реализовать модель состояния фильтров.
- Реализовать стартовую загрузку справочников и первой страницы.
- Реализовать отправку запроса при изменении фильтров.
- Реализовать рендер таблицы.
- Реализовать рендер пагинации и счётчика общего количества.
- Реализовать отдельный клик по `1000+` для точного количества.

## Этап 6. Навигация и доступ - выполнено

- Добавить пункт меню в layout только для администраторов.
- Добавить подсветку активной страницы.
- Проверить, что доступ к странице закрыт для не-админов.

## Этап 7. Финальная проверка - в процессе

- Проверить визуальное сходство с `Users.cshtml`.
- Проверить UX фильтров по мотивам `Report.cshtml`.
- Проверить пагинацию на граничных сценариях.
- Проверить, что список нельзя открыть внутрь заявки.
- Прогнать `dotnet build` после внесения кода.
