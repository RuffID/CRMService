# Этап 3. Тесты Domain и Contracts

Status: Not Started

## Domain.Tests

Проверять только реальное поведение, а не автоматически покрывать каждый getter/setter.

Первая волна:

- `CompositeKeyComparer`: равенство, различие одного компонента, порядок компонентов, null-сценарии и согласованность hash code;
- `EquipmentParameterFieldTypeJsonConverter`: допустимые значения, неизвестное значение, null и round-trip;
- доменные типы с методами копирования/сравнения: копируются ли все значимые поля, не разделяются ли изменяемые коллекции ошибочно;
- константы авторизации и периодов: только те связи, которые являются контрактом поведения, а не дублирование самих значений.

Если у доменных моделей нет поведения и инвариантов, не создавать тесты ради процента покрытия. Новые инварианты в дальнейшем тестировать непосредственно в Domain.Tests.

## Contracts.Tests

Первая волна:

- `ServiceResult.Ok/Fail` и `ServiceResult<T>.Ok/Fail`: согласованность `Success`, `Data` и `Error`;
- `ServiceError`: сохранение status code и сообщения;
- JSON round-trip для ключевых request/response DTO, используемых Razor Pages, API и вебхуками;
- nullable-контракты DTO: отсутствие необязательных полей должно десериализоваться ожидаемо;
- стабильность имён JSON-полей для внешних webhook/request моделей, особенно если используются атрибуты сериализации.

Не делать snapshot всех DTO целиком: такие snapshots создают шум при любом допустимом расширении контракта. Для внешнего контракта проверять только обязательные и исторически чувствительные поля.

## Критерии завершения

- Domain.Tests не ссылается на Application, Infrastructure или Web.
- Contracts.Tests не запускает web host и не обращается к БД.
- Тесты фиксируют поведение конвертеров и результата операции, но не дублируют тривиальные свойства.
